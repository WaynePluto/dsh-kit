# 常驻服务

`@dsh-kit/dsh-plugin-services` 管理有名字的长期命令，例如前后端开发服务器、本地 S3/数据库这类公共基础服务。
服务独立于会话和 dsh 进程；注册表与日志都以 dsh home（`$DSH_HOME`）为作用域，
同一台部署上所有工作区共享：任何会话的面板都能看到全部存活服务，
停止、重启与日志按全局唯一名称跨工作区寻址，日志不再挂在碰巧拉起服务的项目名下。

## 使用

侧边栏「插件」「自动化任务」下方有「服务」面板，点击进入全局管理页面：查看运行状态、
读取日志、停止或重启服务。页面属于部署级（不随会话切换），列表恒为全局——
当前会话工作区的服务排在最前，其他工作区的服务行首带来源项目徽标（悬停可见完整路径）；
没有正在运行的服务时页面显示空态说明。已停止服务的日志仍可通过工具读取。
当前会话处于受限沙箱时，页面上的重启沿用会话自己的批准门控；没有当前会话则拒绝。

| 模型工具 | 用途 |
|---|---|
| service_start | 启动具名命令，支持端口、日志正则或定时就绪探测；名称全局唯一，重名拒绝并指认属主项目 |
| service_list | 列出服务并与操作系统实际进程核对；默认本项目，`scope:"all"` 看所有工作区（排查端口占用） |
| service_logs | 读取日志尾部，包括已停止服务与其他工作区的服务 |
| service_stop | 停止整个服务进程树；任何工作区都可发起 |
| service_restart | 用保存的启动命令重启；是否允许由调用方会话自己的沙箱门控决定 |

普通短命令使用 pwsh/bash；常驻服务不使用 dsh 的会话级 jobs。

## 数据与限制

- 全局注册表：`$DSH_HOME/dsh-kit/services.json`（本 dsh 部署内唯一，跨工作区、跨 profile 共享）；
  全局日志：`$DSH_HOME/dsh-kit/logs/<name>.log`（每个服务名一份当前运行的日志，每次启动截断，总量随服务数有界）。
  隔离 home（如 `~/.dsh-dev`）互不可见。
- 旧版存量（D17 前）：项目内 `.agents/services.json` 在该工作区首次被触达时自动并入全局并删除；
  项目内 `.agents/logs/` 的旧日志经 roots 索引仍可回捞，运行中的旧服务下次 restart 时日志自动落位 home。
- 并发写入由注册表旁的 lockfile 串行化；持有者崩溃留下的陈旧锁会被打破，
  两个窗口同时以同名启动时后写入方会终止自己刚拉起的进程并如实报告。
- 注册表读取时丢弃已不存在的项目目录，来源索引不随历史无限增长。
- 日志在独立弹窗显示，页面没有创建服务的按钮；弹窗可拖动、八向调整，
  右上角关闭按钮旁有全屏开关：全屏时拉满视口并禁止拖动/调整，再次点击恢复原尺寸与位置。
- 页面中每个服务固定单行；端口、pid、时长与命令过长时在中间省略号截断，悬停可见全文。
  服务名列同样中间截断（保留首尾可辨认锚点），宽度不足时先压缩命令列，名称只在自身超宽时截断。
- 用 pid 加创建时间确认进程身份；pid 已复用时不杀，身份不明时拒绝自动停止。
- 身份探针按批进行：一次 PowerShell 子进程取全部 pid 的创建时间（与存活服务数无关），
  展示轮询在 20 秒窗口内复用结果；**停止/重启永远现查**，缓存不能作为终止决策依据。
  读日志只查注册表与 pid 存活（signal 0），不做全量对账；日志尾读取有 256KB 窗口，
  长跑服务的大日志不会拖慢弹窗。
- 页面隐藏时停止轮询，运行状态每 5 秒刷新（也支持手动刷新），时长按宿主快照加本地流逝计算；
  页面打开即显示「正在读取服务…」，首个快照到达后切换为状态行。

## 安全

服务通过 spawn 在沙箱外执行。start/restart 读取**调用方会话**的沙箱模式，
跨工作区操作同一门控：danger-full-access 无需额外批准，受限模式只接受 allowed-once，
缺少会话或批准能力则拒绝——在其他工作区发起重启并不会绕过本会话的批准。
未挂沙箱的组合体没有受限模式。approvalInConfinedSandbox 默认 true，关闭意味着接受服务逃出沙箱。
默认固定 YOLO 下是全权限执行，请阅读 [固定 YOLO 风险说明](../yolo-mode/README.md)。

## 维护与验证

Windows 使用 L1/L2 两级 Node 启动器，注册表记录 L2；不能只靠 detached:true 抵抗 taskkill /T。
PowerShell 使用 NoProfile、NonInteractive 和 UTF-8 前缀。详细契约见 [工具与进程](../../docs/dsh/runtime.md)。

```powershell
pnpm --filter @dsh-kit/dsh-plugin-services test
node scripts/services-check.mjs
```

live 测试验证真实进程存活、日志和停止；仅 mock 测试不能证明这些操作系统性质。
修改插件后必须构建并重启 dsh，再确认既有服务能被认领。

## 分发与管理

本包不作为独立安装项分发，而是 `@dsh-kit/dsh-plugin-development-tools`（开发工具 Bundle）的组件。停用后，常驻服务的模型工具与管理入口消失；已启动的服务进程不会被停止。
可在该 Bundle 详情中单独停用或重新启用本组件；安装、卸载和升级以整个开发工具 Bundle 为单位。
套件安装后本组件默认启用；后续升级以整个套件为单位，并保留 Bundle 与组件的停用状态；卸载后不会自动补回。
需要重装时，在 dsh「添加插件」中填写套件目录 `plugins/suite` 的绝对目录。
