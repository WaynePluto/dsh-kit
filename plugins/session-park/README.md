# 切屏停靠

`@dsh-kit/dsh-plugin-session-park` 解决「停在运行中的会话上切屏，回来永远没有绿点」：
当你离开 dsh 窗口（失焦或最小化）持续 3 秒、且当前会话还在运行时，自动把主视图让给
当前工作区的一个空白会话（官方「新建会话」同一条路径）。之后这个会话结束时，侧栏
行会正常亮起「完成未读」绿点，你一眼就能看到它完成了；点击会话行回到它，绿点清除。

## 为什么需要

上游只有在会话结束时「不在主视图（mainView）」才记完成未读（`SessionStatus.
completionUnread`，上游注释原话 "observed stop outside the main view"）。你正停留的
会话就是主视图，它结束时不记未读；被插件/服务等面板页挡住时也一样（面板页不清
mainView）。于是在多个工作区都有任务时：你停在 A 会话等它跑完、切屏去干别的——
A 结束没有绿点，你回来看到别的工作区有绿点就去看了别人，A 的结果被错过。本组件
在「人已离开」时用纯官方导航动作满足这个判定的前提，不改变上游未读机制。

## 行为与边界

- 出发信号是**窗口失焦或隐藏**（alt-tab 只触发 blur，最小化两者都触发），持续
  **3 秒**且到点时复查「仍离开、会话仍在运行」才停靠：快速 alt-tab 拿个东西、
  失焦后 3 秒内会话恰好结束，都不会动作。
- 停靠动作每个离开周期最多一次；停靠后主视图停在空白会话上（不在运行），再次
  切屏不会重复动作。回来后该干嘛干嘛，组件**不做**「回来自动切回」——自动切回
  会立刻清掉绿点，与初衷相悖。
- 停靠落点是**当前会话所在工作区**的空白会话（复用既有 blank，与原生新建会话
  完全同路径，不会堆积会话）；输入框草稿跟随会话，停靠不丢草稿。
- 面板页（插件/自动化任务/服务）盖住会话时同样生效：停靠会把面板页切回会话列。
- 待操作（黄点，审批/提问/计划确认）与运行中（蓝点）状态点上游不做主视图过滤、
  恒显示，停靠不会让你错过它们；等待审批期间停靠无收益（任务无法推进），但一致
  的行为更可预期。
- 当前视图是子代理会话、或没有主视图会话时，判定为不在运行，不动作。
- 全程官方 Context service（`sessions` / `uiSession` / `uiWorkspace`），零 DOM
  注入、无宿主服务、无设置项；想临时不用在插件详情停用本组件行即可。

## 维护与验证

```powershell
pnpm --filter @dsh-kit/dsh-plugin-session-park test
```

纯浏览器半、无宿主服务；构建落盘后由官方 client-hmr 自动热替换（宿主半无改动、
组件行已装载时无需重启 dsh）。依赖的 `uiSession.adapter.current`、
`sessions.list` 与 `uiWorkspace.startSession` 都是公开契约，上游变更风险低；
完成未读机制的出处与复核要点见 docs/dsh/workspace.md「完成未读的精确机制」。

## 分发与管理

本包不作为独立安装项分发，而是 `@dsh-kit/dsh-plugin-conversation-enhancements`
（会话增强 Bundle）的组件。停用后行为恢复原生（切屏不再停靠），安装、卸载和升级
以整个 Bundle 为单位。套件安装后本组件默认启用；需要重装时，在 dsh「添加插件」
中填写套件目录 `plugins/suite` 的绝对目录。
