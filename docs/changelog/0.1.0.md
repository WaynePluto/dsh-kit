# 0.1.0

本版是重新定位版本：项目从「远程工作站插件套件」收敛为官方 dsh 的**纯插件增强套件**，
并整体更名 dsh-kit（用户文案「DSH 增强套件」）。

## 更名

- 包 scope `@dsh-remote/*` → `@dsh-kit/*`；套件包 `@dsh-kit/dsh-plugin-suite`；
  插件 `name` 字段与 locale 文案同步（例如 `dsh-remote-files` → `dsh-kit-files`）。
- 组件包版本统一为 `0.1.0`。
- 仓库与本地目录名由维护者最后改名；改名后旧套件与旧数据目录不再需要。

## 移除远程能力

- 删除 relay / connector / protocol 三个应用包，以及 `remote-settings`、`remote-runtime`、
  `browser-compat`、`directory-picker-browse` 四个组件与 `remote-experience` 组合包。
- 删除壳级 `remote-privileged`（connection 覆写与主题投影）与 `remote-trust`、`theme-projection`
  两个 display 微包；模型屏障占位实现移入 `@dsh-kit/dsh-plugin-model-bootstrap` 本体。
- 删除 relay 专用脚本与文档（relay CLI、m0 fence 检查、安全/传输/联调验收/启动基准文档、
  开发介质流程 `plugin-distributions.mjs` 与 `media-stamp.mjs`）。
- 不再有项目专属数据目录（`~/.dsh-station`、`~/.dsh-remote`）、配置文件与环境变量；
  配置全部在 dsh 自己的 profile 与 settings 里。旧目录可直接删除。

## 仓库结构

- `packages/plugins/*` 扁平化为根 `plugins/*`；`packages/` 只保留 `plugin-build`（tsdown 配置工厂）
  与 `plugin-ui`（浏览器半共享 UI）。
- 组件数 22 → 18；分发组合 11 → 9 个 Bundle（model-enhancements、conversation-enhancements、
  development-tools 三个组合包 + 六个独立包），全部收进套件单包。
- `pnpm suite:build` 成为套件生成入口；`pnpm plugins:build` 仍为插件产物入口；
  `pnpm check:dependencies` 现在同时覆盖 `plugins/`。

## 开发与验证

- 开发入口 `pnpm dev` 使用 `~/.dsh-dev` + profile `dsh-kit-dev` + 端口 3180；
  不再需要 relay 端口与 station home。
- 冒烟脚本从 `~/.dsh-dev` 的 `dsh-kit-dev` profile 复制隔离副本后启动真实 dsh；
  `concise-mode-check` 改为安装套件并停用/启用整个套件 Bundle；
  `verify-suite-client.mjs` 期望 16 个浏览器行并接受 `--token`。
- notify 删除桌面壳回环通道，只保留 Windows toast（通知没有跳转动作）。

## 升级步骤

1. 在官方 dsh 的插件页卸载旧的 dsh-remote 套件（套件与其组件会一起移除）。
2. 用新版仓库路径执行 `pnpm plugins:build && pnpm suite:build`。
3. 在「添加插件」中输入 `plugins/suite` 的绝对路径，安装后启用并重启 dsh。

旧套件的组件配置与停用状态不随卸载保留，需要重新设置；旧数据目录可以删除。
最后一次带远程能力的状态存档在 git tag `dsh-remote-final`。
